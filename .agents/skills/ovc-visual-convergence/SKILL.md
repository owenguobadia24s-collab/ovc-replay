# OVC Visual Convergence

## Governing sources

Read before changing the console:

- `design/research_console/visual_target/OVC_Research_Console_Visual_Target_and_Convergence_Contract_v1_0.md`
- `design/research_console/visual_target/REFERENCE_MANIFEST.json`
- `design/research_console/visual_target/VT-REF-01.webp` through `VT-REF-04.webp`
- `docs/plans/research-console-vnext/RCN_RN_WP3E_Autonomous_Visual_Convergence_Addendum_v0_1.md`

The repository WebP files are downsampled visual projections; `REFERENCE_MANIFEST.json` preserves the original operator-supplied PNG source identities. The canonical references control composition, density, hierarchy, panel discipline and instrument quality. Prototype data and write-looking controls are illustrative only.

## Goal

Do not merely improve the UI. Converge the exact rendered React head until every blocking `VC-01..VC-18` criterion passes and the candidate visibly belongs to the canonical prototype family while preserving Research-Native semantics and read-only authority.

## Continuous loop

Repeat without requesting operator review for ordinary refinement:

1. **Inspect target** — identify which VT reference is primary for the surface being changed.
2. **Render current exact head** — always establish current evidence before editing.
3. **Compare** — assess composition, primary dominance, density, panel geometry, instrument quality, evidence attachment, domain identity, chrome, whitespace and responsive safety.
4. **Rank discrepancies** — record the five largest visual/product gaps by user impact, not by implementation ease.
5. **Choose one coherent correction batch** — prefer structural improvement over scattered pixel tweaks.
6. **Implement** — preserve typed read-model boundaries, FVT, missingness, denominators, QA, evidence identity and fail-honest states.
7. **Test** — run relevant semantic/component tests. Visual work may not regress semantics.
8. **Rerender** — compare again from the exact new head.
9. **Update the discrepancy ledger** — mark each VC item PASS/BLOCKED and name the next highest-impact gap.
10. **Repeat** until final readiness or a typed stop condition occurs.

## Correction priority

Unless evidence shows another ordering is necessary, work in this sequence:

1. shell and workbench geometry;
2. primary analytical surface dominance;
3. information density and dead-space removal;
4. MatrixView / ProofTimeline / BoundedGraph / AST / evidence-instrument quality;
5. selected-object evidence integration;
6. domain identity and navigation;
7. typography, borders, tabs, controls and micro-panel rhythm;
8. 1440×810 and 1280×720 responsive safety;
9. final accessibility and two-pass stability.

## Forbidden completion shortcuts

Never call the task complete because:

- components exist;
- tests pass;
- the screenshot is cleaner than the prior pass;
- a percentage score is high while a blocker remains;
- only one viewport looks good;
- semantic instruments are still raw table/list/`<pre>` demonstrations;
- the UI is a generic card dashboard or equal-box gallery;
- evidence is visually detached from the selected object;
- write-looking controls leak into the current read-only product.

## Stop conditions

Stop and surface a blocker only for:

- `CONTRACT_CONFLICT`;
- `AUTHORITY_CONFLICT`;
- `TECHNICAL_IMPOSSIBILITY` with evidence;
- `CURRENT_MAIN_CONFLICT` requiring re-preflight;
- `FINAL_G3V_READY`.

Spacing, CSS, typography, density, layout balance, panel sizing, visualization refinement and normal responsive defects are not operator-stop reasons.

## Final readiness

Before declaring `FINAL_G3V_READY`:

- all `VC-01..VC-18` are PASS;
- 1920×1080 is the canonical exact-head render;
- 1440×810 remains usable and compositionally faithful;
- 1280×720 has no hard clipping or authority/evidence loss;
- relevant component/semantic tests PASS;
- required full repository assurance PASS;
- two consecutive exact-head convergence passes show no blocking regression;
- one final candidate and discrepancy ledger are prepared for the operator.
