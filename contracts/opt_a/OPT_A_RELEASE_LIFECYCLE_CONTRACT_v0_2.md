# OPT-A Release Lifecycle Contract v0.2

## Authority

This contract governs release identity, disposition and selector eligibility for the OPT-A v2 GBP/USD programme. It introduces repository governance only. It does not download provider data, build market observations, publish to R2, activate selectors or authorise OPT-B/C/D claims, probability, exposure or execution.

Programme document: `OVC-OPT-A-V2-IMPLEMENTATION-PLAN-0.2`.

Baseline: `a9902c97e21131b1882b4c11ca3a2a79273e7c77`, the squash merge of R0 PR #2. The merge contains reset head `71c7c5513efb9bb8d214d118be03090664050c21`.

## Identity rules

1. A release ID identifies one immutable byte population and one research role.
2. New or regenerated bytes may never inherit `OPT-A.GBPUSD.2026H1.v1`.
3. The exact v2 role identities are:
   - `OPT-A.GBPUSD.DISCOVERY.2021_2023.v2`
   - `OPT-A.GBPUSD.DEVELOPMENT.2024.v2`
   - `OPT-A.GBPUSD.VALIDATION.2025.v2`
4. Discovery, development and validation intervals are fixed, non-overlapping UTC half-open intervals.
5. Selector activation is a separate authority event and is not implied by registration, local verification, publication or remote verification.
6. Rollback may set all v2 role selectors to `NONE`; it may never reactivate historical v1.

## Orthogonal state fields

Every release record must carry these dimensions independently:

- `lifecycle_state`: `DRAFT`, `INTAKE_IN_PROGRESS`, `WORKSPACE_VALIDATED`, `RELEASE_FROZEN`, `LOCAL_VERIFIED`, `PUBLICATION_APPROVED`, `PUBLISHED`, `REMOTE_VERIFIED`
- `authority_state`: `NONE`, `CANDIDATE`, `SHADOW`, `ACTIVE_DISCOVERY`, `ACTIVE_DEVELOPMENT`, `ACTIVE_VALIDATION`, `HISTORICAL`, `SUPERSEDED`
- `qa_state`: `NOT_EVALUATED`, `PASS`, `WARN`, `BLOCK`, `QUARANTINE`
- `availability_state`: `LOCAL_ONLY`, `REMOTE_PRESENT`, `REMOTE_VERIFIED`, `PARTIALLY_AVAILABLE`, `MISSING`
- `publication_status`: `NOT_ATTEMPTED`, `APPROVED`, `PUBLISHED`, `NEVER_PUBLISHED`, `ABANDONED_BY_POLICY`
- `consumption_state`: `NOT_APPLICABLE`, `OPEN`, `LOCKED_UNCONSUMED`, `APPROVED_ONCE`, `CONSUMED`, `RETIRED`
- `selector_state`: `NONE`, `PENDING`, `ACTIVE`, `ROLLED_BACK`, `BLOCKED`

No single lifecycle label may silently imply authority, QA, availability, publication, consumption or selector state.

## Historical v1 disposition

`OPT-A.GBPUSD.2026H1.v1` remains an immutable historical record with these current controls:

- historical seal status: `SEALED_RESEARCH_AUTHORITY`
- lifecycle state: `RELEASE_FROZEN`
- current authority state: `SUPERSEDED`
- QA state: `PASS_HISTORICAL_RECORD_ONLY`
- availability state: `MISSING`
- publication status: `NEVER_PUBLISHED`
- reproducibility status: `NOT_REPRODUCIBLE_MISSING_PAYLOAD`
- R2 canonical status: `ABSENT`
- active selector: `false`
- replacement policy: `NEW_BYTES_REQUIRE_NEW_RELEASE_ID`

Permitted uses are historical lineage, legacy-result reference and governance audit. Prohibited uses are new replay input, canonical publication, parameter sourcing, selector fallback, rollback target and untouched validation.

## Legal-combination rules

- `SUPERSEDED` or `HISTORICAL` releases cannot have an active selector.
- `NEVER_PUBLISHED` and `ABANDONED_BY_POLICY` releases cannot claim `PUBLISHED` or `REMOTE_VERIFIED` lifecycle or availability.
- `ACTIVE` selector state requires an exact release ID, manifest ID, remote verification receipt and operator activation decision.
- `LOCKED_UNCONSUMED` validation may be identity-registered but cannot be consumed without an exact validation-access approval.
- A QA `BLOCK` or `QUARANTINE` state prohibits freeze, publication and activation.
- Missing bytes prohibit reproducibility claims and publication under the missing release identity.

## Gate consequence

WP1 establishes programme identity and registry governance only. WP2 and WP3 may begin after WP1 is merged and its gate packet remains `PASS`. Provider population execution remains blocked until A2-G0 passes.
