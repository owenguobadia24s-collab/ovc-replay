# RO3 Comparison Non-Activation Contract v0.1

Status: `ACCEPTED_AT_RO3_G2` after passing gate evidence.

## Scope

This contract governs C1 computability explanations, null profiles, formula-definition comparisons, lawful release-output comparisons and compact affected-surface traces. Outputs are local, replaceable, read-only derived evidence.

## Computability law

- Every numerical null has exactly one reason from the frozen C1 null and non-computable registry.
- A non-null value has no null reason.
- Empty strings, sentinels, float NaN and Infinity are prohibited.
- Zero-range bars retain valid absolute geometry and null only registered range-divided fields.
- Prior-close fields use only the immediate contiguous admissible prior bar with exact release, manifest, instrument, clock and side identity.
- Source-inadmissible, control-clock, unresolved-lineage and Validation inputs emit no C1 record and remain visible through reconciliation evidence.
- Validation is denied before path, object, record, row or timestamp resolution.

## Comparison law

Every comparison begins with a `NON_ACTIVATING_EVIDENCE_HEADER`. Detailed diff disclosure requires an exact frozen append-only acknowledgement bound to the comparison identity, operator identity and unexpired access window.

The acknowledgement:

- grants no formula, release, selector, threshold, semantic or market authority;
- is not an approval record;
- cannot select a winner;
- cannot activate or promote any version;
- cannot unlock Validation;
- cannot authorise probability, risk, exposure, trading, execution or agent action.

## Comparison classes

`IDENTICAL_DEFINITION`, `CONTRACT_CHANGED`, `FORMULA_CHANGED`, `DOMAIN_CHANGED`, `NULL_POLICY_CHANGED`, `CHRONOLOGY_CHANGED`, `SYMMETRY_CHANGED`, `SERIALIZATION_CHANGED`, `POPULATION_CHANGED`, `OUTPUT_CHANGED`, and `NOT_COMPARABLE`.

Discovery and Development may be contrasted only through `ROLE_CONTRAST`; they are never described as equivalent releases. Release-output comparison requires exact instrument, role, clock, side and source-population preflight.

## Affected surfaces

C2 and Pattern Discovery references are compact trace-only metadata. They must be presented in a separate bannered panel. A C1 null explanation and a C2 transition must never appear in one compact card. No downstream payload is duplicated, diagnosed, tuned or rewritten.

## Identity and reproducibility

Logical identities use SHA-256 over canonical JSON with sorted keys and deterministic list order. Absolute paths, machine identity, runtime and presentation order do not enter logical identity. One-byte changes to source definitions, populations or outputs change the relevant evidence hash.

## Prohibited writes and authority

Writes to C1 records, formulas, releases, selectors, OPT-A, C2, Pattern Discovery, R2, Validation, thresholds, semantics, probability, risk, exposure, trading, execution, agents or the primary branch are prohibited.
