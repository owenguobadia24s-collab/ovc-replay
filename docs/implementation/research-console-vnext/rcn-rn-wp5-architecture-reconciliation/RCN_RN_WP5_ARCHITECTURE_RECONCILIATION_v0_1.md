## Purpose

Reconcile the source-faithful WP5B/WP5C Research Console implementation topology with the owner systems now materialised on current main, without rewriting the ratified v0.3 Research-Native plan, changing WP5A, granting any first-new Research-source exposure, or altering scientific/Validation/execution authority.

## Preserved governing semantics

The original WP5B safeguards remain binding: one canonical DMRP `ResearchCandidateGeneration` constitution; Path correspondence is not independence; no Path winner meter; negative/divergent evidence remains visible; the Console may not merge, repair, promote or create candidate/theory/semantic authority.

The original WP5C safeguards remain binding: frozen candidate identity is immutable; downstream evidence cannot repair earlier definitions; Validation remains locked and separate; protected Validation resolution is denied before object/path/timestamp/count resolution; evaluation presentation creates no candidate/model/semantic/probability/risk/exposure/execution authority.

The source-faithful `GOVERNING_SCOPE.md` and original WP5A/B/C packet manifests remain immutable historical/governing records. This packet is an implementation-topology overlay only.

## Reconciled owner map

### DMRP
Owns Path 1 / Path 2 research modes, immutable Research Operations records, `ResearchCandidateGeneration` identity, mode provenance and generation semantics. Console treatment: direct source-bound presentation only; no candidate construction or repair.

### RCCR
Owns Research Coverage Matrix, typed gap queues, METHOD_FIRST routing, Path-1/Path-2 correspondence, independence/exposure projection, and descriptive non-effectuating Next Research Route. Console treatment: project canonical RCCR read models; do not reimplement cross-mode interpretation, ranking, coverage scoring or route selection.

### PRSC / EC1
Owns preregistered scientific challenge protocol, representation/temporal/context challenge evidence, multiplicity accounting, scientific review/disagreement/limitation records, and later challenge results when separately authorised. Console treatment: protocol/readiness/state may be presented when lawful; real decision-bearing challenge results fail closed until owner authority prerequisites are met.

### OPT-C / OPT-D
Own downstream frozen-candidate evaluation evidence. Console treatment: read-only presentation only; no candidate repair, promotion or Validation crossover.

### System Atlas
Owns repository-wide ownership, authority, dependency, history, impact, explain and why-blocked query semantics. Console treatment: optional deep-links/projections only; Atlas is not a correctness dependency until separately authorised for operational reliance.

### Research Console
Owns federated read-only presentation, navigation, filtering, comparison layout, evidence drill-down, explicit absence/missingness/capacity/authority state, and source provenance. It owns no scientific transformation, research prioritisation, candidate identity, challenge disposition or evaluation semantics.

## Per-source G5 admission

`RCN-RN-G5-FIRST-NEW-SOURCE` remains the operator boundary, but admission is explicitly source-by-source. A PASS or pre-authorised read surface for DMRP does not transitively admit RCCR, PRSC/EC1, OPT-C or OPT-D. For every owner source, Console preflight must independently establish one of:

1. fixture/shadow/non-evidentiary presentation only; or
2. exact pre-existing owner authority permitting this Console read presentation; or
3. explicit operator PASS for that first-new real Research-source exposure.

Source existence, filesystem readability, route presence, scientific authority, or another source's G5 decision never implies Console presentation authority.

## System Atlas integration rule

Where Atlas is lawful and available, Console components may deep-link/project its canonical query results. Where Atlas reliance is not authorised or materialised, the Console presents typed unavailability and retains its own source identity/authority labels; it does not synthesize Atlas answers.
